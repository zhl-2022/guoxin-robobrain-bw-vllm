本项目以先前“参赛任务设计”聊天和当前赛事文档为依据。先前聊天里的实施包下载地址属于另一运行环境，当前未取得该 ZIP；本地代码基于已读取的方案和赛事 PDF 实现。

## 3. 卡时预算

卡时 = 加速卡数量 × 实例运行小时。额度采用平台实际值，每次开机、关机记录时间、卡数与余额；本地预算仅作估算，不替代平台计费。

| 用途 | 规划上限（卡时） | 执行条件 |
|---|---:|---|
| 工具链和首件环境 | 20 | CPU 准备完成，原生版本匹配 |
| 首批六模型 | 180 | 逐件通过功能关卡再进入正式精度 |
| 同架构复用、卡型和框架扩展 | 100 | 官方确认独立任务可用 |
| 图像、语音生成及专项探索 | 80 | 前序成果可复现，有专用评测材料 |
| 正式复跑、返工、风险储备 | 117.1058 | 保留到最终复现和提交检查 |
| 合计 | 497.1058 | 以平台剩余额度滚动调整 |

首轮加速卡探索只使用 1 卡，单次上限 2 小时。启动失败、依赖 ABI 不匹配、关键材料缺失时先退出进程和关机，再分析；无有效进展不延长。服务进程退出不会让 Notebook 自动停止计卡时，必须单独验证平台关机状态。无卡准备阶段不占加速卡时，费用以实际页面为准。

上表是早期全部模型的额度分配草案，**不是本轮开卡或支出安排**。本轮三题本地准备不分配 GPU；正式材料与首档实测就绪后再重估三题预算。既有余额是 2026-10-19 关机后的快照，本轮未刷新平台余额。

## 4. 交付关卡

1. 核对任务适用口径，取得可供评审获取的完整镜像地址/tag、模型完整文件及哈希；digest 为可选增强信息，不增设认领回执门槛。
2. 验证设备、依赖、模型结构和启动参数，运行单图、多图、多轮、流式功能检查。
3. 使用原样保存的官方 baseline、评测器、固定子集及模板，全部必选指标独立通过。
4. 完成官方规定的全部性能档位和连续两轮记录；保留失败与超时。
5. 从干净镜像复跑，对照精度及性能。
6. 完成八章报告、独立提交目录、镜像与仓库，进行提交前检查。

工程测试、功能 Smoke、官方评测、官方接受四种状态分别记录。缺少官方材料时 CLI 返回未就绪，禁止把内部测试或参考 Transformers 推理标为正式通过。
