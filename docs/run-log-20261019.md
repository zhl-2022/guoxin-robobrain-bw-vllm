### RoboBrain

两个 BF16 分片完整 SHA256 与发布方固定 revision LFS 元数据一致，共 750 张量、17,534,247,392 字节 payload。22:40:34 启动、22:42:24 就绪的 baseline001 在七项通用传输检查中通过，但把红方块描述为人物合照，定位/点选也异常；部分输出达到 token cap。原始回答保留，不能把 HTTP 成功算适配成功。

同权重、同图片在原生 Transformers 5.5 / SDPA math 的三个参考生成中能识别红方块、蓝圆和文字标签，见 `robobrain-reference-gpu-001.json`；每条 64 token cap 有截断，计时不当作服务性能。实际安装的视觉源码、HCU 分派、custom-op 路径已保存。此前怀疑的 OOT 跳过 contiguous 不成立：当前 HCU 是 ROCm，未注册 OOT MMEncoderAttention。

项目局部 worker 扩展 `robobrain_vision_math_diagnostic.py` 仅对 head72、384/768 patch 的 fixture 输入选用 SDPA math。Math002 的同提示词返回正确红方块/蓝圆，grounding `[60,233,350,780]`、pointing `[(237,516)]`，54 次真实 eligible 调用全部完成，随后停止。此阶段只证明问题与视觉 SDPA 分派路径有关，尚未定位具体 fused kernel 根因。

进一步实现 head72 全尺寸的 query 分块 math 候选：每个 query 块保留该图全 K/V，原框架仍负责分图边界，最多 128 query/块。18 项 BW 数值对照通过，最大绝对差 0.0009765625；含 BF16/FP32、GQA、非整块长度、分图隔离和非目标 head64。候选未修改原生包，带两份实际源码 hash guard。单个 score FP32 张量预算 64MiB 不等于总显存峰值，通用 head 广播的限制见 task。

Run003 使用原生默认的 65536 视觉 patch 做初始化 profiling，math 分块计算较慢，已主动停止并保存 `robobrain-vllm-profile-*-003.*`。随后 Run004 显式用 1024×1024 dummy profiling，实际 heldout 图片尺寸为 640×448 和 512×512；本轮尚不覆盖官方大图内存/性能策略。所有失败和被中断的启动均保留。

Run004 最终在 23:31 左右就绪并完成七个新图片请求。实际 attention 视觉长度 1120、1024，81 次 math 调用全部完成；单图描述和双图比较正确，合成框 IoU 分别 0.8839659403/0.9024416624，两个点选均在框内。定位诊断不当作官方指标，trajectory 没有真实深度 ground truth。服务随后停止，完整日志和 state 已归档到 `robobrain-*-004.*`。该轮初始化 profile 4096 patch，未改变两张真实图片。
