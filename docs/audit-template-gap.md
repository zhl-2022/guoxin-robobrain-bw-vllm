## 4. 每题专有差距

### 4.1 Recon2Reason × BW × vLLM × BF16

已有原生 BF16 vLLM 服务及七项图文接口检查；无额外依赖，`requirements-extra.txt` 留空与当前路径一致。纯原生路径没有代码 patch 时，模板允许如实说明无改动，不应为了目录齐全制造 patch。

- [ ] 确认本模型属于 T02 的哪一种精度口径：OCRBench/MMMU、对应 VQA，或另行指定空间推理数据；现有 `task.json` 的 OCRBench 是待验证配置，不能代替官方确认。
- [ ] 取得专属 evaluator、baseline、固定样本、最大输出、思考开关及图像分辨率。
- [ ] `verify.sh` 当前只桥接外部官方脚本；它不会运行 `--selfcheck`，且要求自拟的 baseline JSON 字段 `model`、`metrics`。取得真实文件后需确认字段匹配，不能要求官方材料迁就当前桥。
- [ ] `bench.sh` 也只是桥，必须另指向已有的正式 benchmark；目前不能单靠它跑出六档。桥额外要求非空 baseline/data/IMAGE_RES 是当前实现约束，不能反推为官方性能脚本的全部前置条件。
- [ ] 固定成功运行的完整参数。目前默认 `EXTRA_ARGS_JSON` 仅 eager，历史成功命令还有 `--max-num-seqs 4` 与 `--limit-mm-per-prompt '{"image":2,"video":0}'`，默认重跑不完全等于已保存成功配置。
- [ ] 检查多轮空间位置回答不足等语义问题，随后完成正式精度、性能和干净环境复跑。

工程交付路径较简单，但目前还不能仅凭七项功能检查提交为整题完成。

### 4.2 RoboBrain × BW × vLLM × BF16

已有真实原生错误、Transformers Math 对照、通用 head72 分块 Math 候选、18 项 BW 数值对照及新尺寸图像功能证据。默认 `run.sh` 保留原生路径，成功候选必须显式 `run_compat.sh`。

- [ ] 确认适用的具身/VLA或视觉理解评测口径。不能自行把通用「动作/坐标与 GPU 参考解析一致率 ≥98%」视为该题已经确认的唯一门槛，也不能未经确认只套 OCRBench/MMMU。
- [ ] 取得官方图片集、参考输出、坐标/动作解析器、固定 prompt、解码参数、输出限制及范围。
- [ ] 将成功的 `robobrain_vision_math_compat.py` 和 worker extension 启用方式纳入完整交付；注明目标源码 hash、平台/版本保护、计算分块、为何影响原错误、精度/性能风险。若按官方 `patches/` 形式提交，提供可重放 patch；若保留项目插件，则需清晰说明等效重放方式并核实模板接受方式。
- [ ] 以最终候选作为启动默认或唯一清晰入口，避免评审照 `run.sh` 命中已知原生错误；统一当前 README 中旧的 pending 与已完成字段。

这是当前三题中改动与性能风险较多的一题；小图恢复和合成框 IoU 不能替代正式数据集。

### 4.3 Qwen3-ASR × BW × vLLM × BF16（T04）

已有权重身份与 legacy BPE 校验、保留原生栈的独立音频 venv、TF5.5 配置顺序兼容插件，以及中英文两条自有合成音真实转写。

- [ ] 将 `qwen_asr_tf55_compat.py`、entry point 元数据、版本/源码 hash 保护与自动加载都随交付；逐项说明改动、原因和精度影响。纯项目插件不等于已生成模板中的编号 patch。
